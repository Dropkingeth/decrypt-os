# Decrypt frontend design

Apply to interface construction or a requested layout change. Work within the existing product unless the brief asks for a redesign.

1. Identify the audience, primary task and existing interface conventions from the brief and current screen. Resolve only missing choices that materially affect the work. State a concrete information hierarchy before editing.
2. Inventory the real content and interaction contracts. Preserve actions, state, data sources, labels with domain meaning and authorization boundaries. Distinguish live, delayed, historical, empty and unavailable data. Do not create realistic-looking placeholder facts.
3. Put the main decision or next action first. Group related information; remove repeated summaries, decorative labels and nested cards that add no meaning. For dense analysis, surface a small set of source-supported primary references and provide a disclosure for the rest. Keep invalidation and material limitations visible.
4. Reuse the product's typography, colors and spacing for a focused cleanup. For a new visual identity, choose a small coherent token set grounded in the subject. Use decoration only when it communicates hierarchy or state. Avoid imposing a preferred font, palette or dramatic redesign on an unrelated task.
5. Write interface labels as plain actions or useful facts. Keep action names consistent from control to result. Explain errors with the cause and a supported next step. Avoid implementation jargon unless it helps the user make a choice.
6. Build with semantic controls and predictable interaction. Preserve keyboard access, visible focus and readable contrast. Support narrow viewports and zoom without clipping important content. Respect reduced motion. Keep images proportional and provide a full-size view when chart detail needs it.
7. Verify the actual affected interactions and states. Use real or faithfully identified fixtures, including long text and missing data. Inspect desktop and mobile screenshots. Check disclosures, keyboard behavior, focus, chart dimensions and unchanged source values. Report unverified states rather than implying that compilation proves usability.
8. Review the changed screen against the brief. Remove one unnecessary visual or verbal element where it improves clarity. Finish with the smallest scoped change that solves the requested problem; retain complete evidence rather than silently dropping it.
